# BE-01 Meta lists contract and endpoint

**Goal:** add the `MetaListsResponse` contract and `GET /api/meta/lists`, which returns the fixed lists and the lab rooms. **Automates:** TC-1.1, TC-1.2, TC-1.3, TC-2.1. **Contract:** [story.md § API contract](../story.md#api-contract)

## Files

- create `packages/shared/src/schemas/meta.ts`, `packages/shared/src/schemas/meta.test.ts`
- change `packages/shared/src/index.ts`
- create `apps/api/src/modules/meta/lab-room.entity.ts`, `meta.service.ts`, `meta.controller.ts`, `meta.module.ts`
- change `apps/api/src/app.module.ts`
- create `apps/api/test/meta.int.test.ts`

## Approach

1. **Contract** (`schemas/meta.ts`): `ListItem`, `LabRoom` (`id: z.uuid()`) and `MetaListsResponse`, exactly as in the story. Copy the style of `schemas/health.ts` (S01.1 BE-01): the schema and its type share a name. Export them from `src/index.ts`. `meta.test.ts` covers TC-1.3.
2. **Entity:** `LabRoom` on table `lab_rooms` with `id` (uuid primary key, generated by the database), `code` and `name`. It must match the `CreateLabRooms` migration exactly, so no new migration is needed. Check this: with `synchronize` off, a mismatch only shows up as a failing query.
3. **Module:** `MetaModule` imports `TypeOrmModule.forFeature([LabRoom])`; add it to `AppModule.forRoot`. Follow the health module from S01.1 BE-05: thin controller, logic in the service.
4. **`MetaService.getLists(): Promise<MetaListsResponse>`:** map each shared constant (`HAZARD_TYPES`, `PROTECTIVE_EQUIPMENT`, `HAZARD_PICTOGRAMS`, `CATEGORIES`, `HAZARD_LEVELS`) to plain `{ value, label }` objects in their defined order. Load the rooms with `repository.find({ order: { code: 'ASC' } })` and map each one to `{ id, code, name }`; never return the entity. A repository error goes on to the `ErrorFilter`, which gives 500 `INTERNAL_ERROR` (AC2); don't catch it.
5. **`MetaController`:** `@Controller('meta')` with `@Get('lists')`, giving `/api/meta/lists`. Public (design §9); add the same comment as on the health controller.
6. **`test/meta.int.test.ts`:** copy the structure of `test/health.int.test.ts` (`createTestApp`, Supertest, schema parse).
   - TC-1.1 and TC-1.2: deep-equal against the shared constants, and the four rooms of the migration.
   - TC-2.1: `vi.spyOn(app.get(getRepositoryToken(LabRoom)), 'find').mockRejectedValueOnce(new Error('relation secret'))`; check that the 500 body does not contain `relation secret`.
7. **Proof of work:** `pnpm verify` (this includes the new integration tests on `labsafe_test`).

## Out of scope

The web app (FE-01 to FE-03). Caching. Any list editing (PRD R4: OUT).

## Implementation notes

**Done (2026-10-29).** Contract `ListItem`, `LabRoom`, `MetaListsResponse` in `packages/shared/src/schemas/meta.ts`, exported from `src/index.ts`; `meta.test.ts` covers TC-1.3. `MetaModule` (entity `LabRoom`, `MetaService.getLists`, public `MetaController` at `GET /api/meta/lists`) is registered in `AppModule.forRoot`. The service maps every list item and room to a plain object and does not catch repository errors, so the `ErrorFilter` answers 500 `INTERNAL_ERROR` (AC2). `test/meta.int.test.ts` covers TC-1.1, TC-1.2 and TC-2.1 and calls `resetTables()` first, as `apps/api/CLAUDE.md` requires.

**Migrations:** none. The entity matches `CreateLabRooms1793232000000`.

**Differences from the ticket:**

- **`apps/api/src/db/data-source.ts` changed (not in the Files list):** added `uuidExtension: 'pgcrypto'` and `installExtensions: false`. Without them, `@PrimaryGeneratedColumn('uuid')` makes TypeORM run `CREATE EXTENSION IF NOT EXISTS "uuid-ossp"` on every connect, which changes the schema outside migrations. It would also use `uuid_generate_v4()` instead of the migration's `gen_random_uuid()`, which is built into PostgreSQL 13+. Later uuid entities get the same behaviour.
- **The entity also mirrors the constraint names:** `lab_rooms_pkey`, `@Unique('lab_rooms_code_key')`, `@Check('lab_rooms_code_check')` and `@Check('lab_rooms_name_check')`. Without them, a later `db:generate` would produce a migration that drops and recreates these constraints.
- **Two tests beyond the ticket's list:**
  - `TC-1.2 the LabRoom entity matches the migrated lab_rooms table`: TypeORM's schema builder `log()` must report no pending query. This makes the step 2 check permanent, and it is read-only on `labsafe_test`. I confirmed it fails when the `@Unique` is removed.
  - `TC-1.1 takes no input: a query string changes nothing`: the endpoint has no input, so this stands in for the "invalid input" rule.
- **No 401/403 test:** no role is refused in this story.
