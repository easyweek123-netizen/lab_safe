## Round 1 · 2026-11-25 · verdict: APPROVE

`pnpm verify`: ✅ (exit 0, run by the main session: shared 129, API unit 133, web 217, integration 283, docs-check OK); `pnpm e2e` 56 passed (reported by FE-02)

AC1–AC8 are built as written, and each has a real test titled `S03.2 AC<n>`. Both routes are `@Public()` with the visibility rule in `SubmissionsService` (E03-D4). `read` answers 404 without a query to anonymous, pending and rejected callers. It filters by `submitted_by` for everyone except an approved admin. `update` answers 404 to everyone except an approved author, an admin included (design open question 1). The id is parsed with the shared `SubmissionIdParam`, and `mine` is declared first and still answers (tested). `PUT` runs in one `dataSource.transaction`. It locks `id AND submitted_by AND status = 'PENDING'` with `pessimistic_write`, then runs S03.1's `checkReferences` on the same manager. It updates the content from `contentColumns(content)` only, and deletes and re-inserts the hazard and PPE rows from the parsed body. This is E03-D5, and it reuses S03.1's helpers instead of copying them. Optional texts parse to `null`, so `update()` really clears them: the AC2 test switches training to "No" and finds `training_given_by` null. `kind`, `status`, `submitted_by` and `submitted_at` cannot change: a test sends all four in the body. The response comes from one joined query through `toSubmissionResponse`, so no email or entity leaks. The integration "unchanged" checks compare the whole stored set, including `updated_at` and the child rows. They cover every AC3 case, the AC5 matrix (with the same body as an unknown id), a non-pending revision, a foreign photo on someone else's page and a foreign `Origin`. Integration tests cover AC7, and the e2e journey covers it from a fresh context.

On the web, the hooks go through `apiGet`/`apiSend` with the shared schemas. `useUpdateSubmission` uses `networkMode: 'always'` and does not touch `['auth', 'me']`. It invalidates `['submissions', 'mine']` and `['submissions', id]`; the AC2 test sees the second read. The page shows the load error and "Page not found" only while there is no data. The form's `defaultValues` are read once, when it mounts. The background-refresh tests (500, other content, 404) prove the typed description, the form and the button stay. Every AC6 state has a component test: loading, unknown, malformed (no request sent), a server 400, an admin, the load error with Retry, a lists failure, the four save failures and offline. The route sits under `RequireAccount level="contributor"`, and `apps/web/CLAUDE.md` lists it. No test was weakened: the S03.1 AC16 tests still check the name as text, and the link test is new.
