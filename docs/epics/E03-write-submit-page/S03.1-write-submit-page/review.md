The shared `SafetyPageContent` names every gap in one parse: the cross-field rules run with `when` and check each value's type first, so `{}` gives exactly the AC9 list. A test proves the AC15 matrix, with the same body as an unknown id. The guards run before `FileInterceptor`, and a test proves that a pending account sending 5 MB + 1 byte gets 403, not 413. `sharp` decides the type from the bytes. AC7 checks the EXIF, XMP and IPTC markers in the stored bytes and the applied orientation. The submit checks the room and the photo owner inside `dataSource.transaction` before any insert, then writes all four tables from the parsed body only. A test with `status`, `kind` and `submittedBy` in the body proves those keys are ignored. `listMine` selects four columns, ordered `submitted_at DESC, id DESC`, on an indexed column. The migration matches the entities: the schema-builder check runs in `safety-page-tables.int.test.ts`, and `down` drops everything in reverse order. Every state in "UI states" has a component test. The e2e journey runs at both widths. No test was weakened: the only removed lines in changed test files are import lines that were extended.

Developer points:
- **1, the training CHECK and `search_vector`:** BE-02 is right. Without `IS NOT NULL`, `training_required AND btrim(NULL) <> ''` is NULL, the whole CHECK is NULL, and PostgreSQL lets the row through. The test `training required without who gives it (23514)` proves the fix. Leaving out `search_vector` follows E03-D6. Both go into design.md, see F3.
- **2, BE-01's open contract choices:** accepted. The limit messages, list messages and issue paths are consistent. `field-labels.test.ts` proves that the web names every path they produce, and the `[]`/`false` defaults keep the `{}` answer at exactly the AC9 list. They are recorded in BE-01's "Differences", so nothing is hidden from the plan.
- **3, BE-03 written before its tests:** acceptable, no finding. Each test asserts a concrete result that would fail if the code were wrong: status and code, row count, `content-type`, the absence of `Exif\0`, XMP and `Photoshop 3.0` markers, and 800 × 1600 after orientation 6. The interceptor is the right place. It sits before `FileInterceptor` on this one route, so the JSON body parser's 413 stays `REQUEST_REJECTED`, and the `BadRequestException` it maps can only come from multer here (`AppException` does not extend it).
- **4, the GHS pictograms:** accepted, as design open question 4 chose. They are the UNECE symbols, public domain on Wikimedia Commons, with their source in `ghs-symbols.ts`. A scan of the nine files found no `<script>`, event handler or external `href`. They are loaded as `<img>`, so an SVG could not run a script anyway.
- **5, the default empty `GET /submissions/mine` handler in `msw.ts`:** accepted. Without it, every older test that lands on `/contribute` would fail on an unhandled request. It hides nothing. The AC16 tests that need a list set one with `mySubmissionsHandler(…)`, and the loading and error tests override it.
