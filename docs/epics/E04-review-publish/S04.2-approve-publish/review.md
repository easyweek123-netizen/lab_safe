## Round 1 · 2026-11-26 · verdict: APPROVE

`pnpm verify`: ✅ (exit 0, run by the main session: shared 171, API unit 139, web 311, integration 367, docs-check OK); `pnpm e2e` 70 of 70 (reported by FE-04)

AC1 to AC15 are built as written, and each has a real test titled `S04.2 AC<n>`. The shared contract adds `ALREADY_REVIEWED` and `SUBMISSION_CHANGED`, `version` (a whole number of at least 1), `ApproveSubmissionRequest`, `ReviewDecision`, `InstrumentSlugParam`, `PublishedSafetyPage` (with `lastApproved` required and no contributor, email, note or `version`) and `slug` in `Submission` and `SubmissionSummary`. The API and the web both use these schemas.

**Data (AC3).** The migration matches the entities, constraint names included. The schema builder finds no difference, and `down` is tested by running it in a rolled-back transaction and comparing columns, constraints and indexes. TypeORM could express the composite foreign key `(id, published_revision_id) → instrument_revisions (instrument_id, id)`, so the design's fallback was not needed. Every refused row from AC3 is tested by its constraint name. That covers another instrument's revision, slug without a pointer and the reverse, a duplicate slug, eight bad slug forms, each review-column combination, and version 0 and -1. An E03-style pending row still inserts with `version` 1.

**Approving (AC1, AC2, AC8, AC9, AC13).** `ReviewService.approve` runs in one `dataSource.transaction` and uses `manager` for every query. It locks the revision `FOR UPDATE`, checks the status and then the version, and locks the instrument. Only when the instrument has no slug does it take `pg_advisory_xact_lock` and choose one, then it writes both rows. Under READ COMMITTED, the slug query runs as a new statement after the lock is granted, so it sees the slug of an approval that has just committed. The integration tests prove the concurrent cases: two same-name approvals at once get two addresses, and two admins approving at once get one 200 with the first as reviewer. `PUT` adds 1 to `version` in SQL under the same row lock, and a refused save leaves it unchanged. The log line has ids only.

**Access (AC10, AC11, AC12).** `@Admin()` on the controller refuses before the pipe or the service runs. The tests cover anonymous 401, then pending, rejected, contributor and author 403, with no page name in the body. A malformed id, an unknown id, six bad bodies and a foreign `Origin` are refused, and nothing changes. The author's `PUT` on an approved page is 409, and the response body is checked. Anonymous, pending, rejected, another contributor and both admins get the same 404 body as an unknown id. `PublishedInstrumentsQuery` joins through `published_revision_id` and also filters `APPROVED`. It is the only public read. `PhotosService` serves a published revision's photo to anyone and keeps the E03 rule for every other photo. An unsubmitted photo of the author stays private after approval. No module cycle: `InstrumentsModule` imports only TypeORM.

**Web (AC1, AC4, AC6, AC8, AC9, AC10, AC14).** `DecisionPanel` sits between the submitter line and the view, which is tested by DOM position. It sends the loaded `version` and shows "Approving…" disabled while it runs. It then goes to `/admin/review` with the confirmation and a link that only accepts an `/instruments/` path. There is one `alert` per failure with the AC8, AC9 and AC14 texts, and no `me` refresh after a failed approve. `SafetyPagePage` follows the edit page's state logic: loading, not found (also for a 400 or a slug too long, with no request), the alert with Retry only while there is no data, and the page kept after a failed refresh. It keeps one h1 in every state. "My submissions" links an approved row to its public page and offers no edit link. The edit address shows the AC10 note and link instead of the form. **e2e** runs the full journey at both widths. It includes AC5's line-by-line text comparison for the admin and the anonymous visitor, AC12's three anonymous checks before and after approval, AC7's box check at 375 × 812, and AC13.

It is the project's normal answer for a param outside its schema (as for `SubmissionIdParam`), and the web shows "Page not found" for it without a request. The contract still lists only 404: see F2. Setting no cache headers on the public read and keeping `private, no-cache` on the photo is safe; nothing asks for caching (M1 and M2 are measured in E06).
